# 设计总览

## 一、定位

一个在 VPS 上安装和管理代理节点的脚本。

- **给谁用**：第一次搭节点的人。假设用户只会"登录 VPS、粘贴一条命令、按回车"。
- **做到什么**：默认不需要域名、不需要做选择，回车一次就得到能用的节点；想要更多时，约 15 种协议可以同时运行。
- **怎么做**：Xray 和 sing-box 两个内核各司其职。用户只选协议，由脚本决定交给哪个内核。

## 二、设计原则

| 原则 | 含义 |
|---|---|
| 默认即可用 | 每个问题都有默认值；推荐档全程不提问 |
| 冲突要明说 | 两个选择互相矛盾时，停下来用人话解释原因并让用户取舍，不替用户悄悄决定 |
| 先校验再生效 | 任何改动先生成新配置并校验，通过才替换；失败自动回到上一份 |
| 出问题能自查 | 体检覆盖最常见的故障，并给出下一步 |
| 不乱动系统 | 不安装或替换防火墙，不碰已有网站和其他脚本的文件；卸载按清单还原 |
| 明文可审计 | 不加密、不混淆、不在运行时下载其他脚本；内核下载后校验哈希 |
| 隐私优先 | 零遥测；默认不记访问日志；不经过任何第三方转换服务 |
| 不过度承诺 | 没有协议能保证不被封。设计重点是被封后恢复得快 |
| 不夹带私货 | 没有推广链接；不替用户悄悄屏蔽任何网站，默认启用的每一项限制都看得见、关得掉；不依赖作者自有的任何服务器 |

## 三、范围

**做**

- 双内核安装、版本管理、更新与回滚
- 约 15 种协议，见[协议与内核](02-协议与内核.md)
- 冲突检查，见[冲突规则](03-冲突规则.md)
- 多用户
- 节点输出：分享链接、二维码、sing-box 与 Mihomo 客户端配置、可选订阅
- IPv4 / IPv6 / 双栈的节点地址模式
- 域名与证书、伪装站、CDN、Argo 隧道
- 出口与分流：WARP、IPv4/IPv6 优先级、按域名分流、链式中转
- 体检、备份恢复、干净卸载

**不做**

| 不做 | 原因 |
|---|---|
| 网页管理面板 | 多一个对外暴露的服务，与隐私优先矛盾 |
| Serv00 等免费主机的保活 | 有封号风险，且与 VPS 场景差异大 |
| Psiphon 分流 | 稳定性反馈较差，收益有限 |
| Telegram 推送 | 会把节点信息送到聊天平台。推送到用户自己的私有仓库则保留，见[隐私与安全](05-隐私与安全.md) |
| 客户端 | 只管服务端；客户端用现成的 |

## 四、与两个参考脚本的关系

只参考功能，不复用代码。

| 来源 | 借鉴 | 改进点 |
|---|---|---|
| mack-a/v2ray-agent | 双内核、协议组合、单项修改、用户管理、分流出站、端口跳跃 | 两个内核互不删除对方；不替换用户的防火墙；CDN 域名与直连域名分开；支持备份恢复 |
| yonggekkk/sing-box-yg | 回车即装完的简单模式、自签与正规证书切换、本地生成节点、双栈自适应、Argo 双隧道、推送到私有仓库的订阅、打开菜单时提示更新 | 内核版本锁定，升级前校验；证书申请前预检；BBR 等系统设置持久化 |

对应的用户反馈见[痛点依据](10-痛点依据.md)。

## 五、关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 内核 | Xray + sing-box，按需安装 | 各有对方没有的协议；只装用到的，小内存机器不白占资源 |
| 谁选内核 | 脚本 | 每种协议固定一个内核，用户不需要理解内核差异 |
| 默认方案 | 无域名 | 域名和证书是新手失败最多的环节 |
| 配置的存放 | 状态文件为唯一事实来源；内核配置是生成物，按协议拆成多个文件 | 备份只需一个目录；不依赖 jq；回滚简单；改一个协议只动一个文件 |
| 自定义配置 | 提供 `custom/` 目录，由内核合并加载 | 满足高级用户，又不破坏"配置是生成物" |
| 外部文件 | 内核、隧道程序、证书工具全部锁版本并校验哈希；运行时不执行远程脚本 | 上游被篡改时不受影响；也因此可以安全地走镜像下载 |
| 域名模式的 443 | Nginx 按 SNI 分流 | 每个协议用不同子域名即可共用 443，Reality 也能参与 |
| 自签证书 | 配合指纹固定，不用"跳过验证" | 防止连接被中间人冒充 |
| Hysteria2 默认端口 | UDP 443 | 伪装成 HTTP/3 的流量出现在这个端口最自然 |
| 语言 | 中文、英文，文案与逻辑分开 | 一开始就分开成本最低 |
| 代码混淆 | 不做 | 审查方看的是流量而不是源码，混淆挡不住识别，却会让用户无法审计。真正的防护是每次安装随机生成所有线路可见的值 |
| 内核版本 | 脚本内锁定已测试的版本 | 两个内核都有过破坏性变更，自动追最新版会导致配置失效 |
| 代码组织 | 源码按模块拆分，发布时合成一个明文单文件 | 既便于维护，又保证用户拿到的是一个可通读的文件 |
| 节点地址模式默认值 | IPv4、IPv6 分开 | 不需要域名；本地 IPv6 有问题时不受影响 |
| 订阅 | 默认关闭；只走加密连接；提供私有仓库、域名、隧道三种途径 | 订阅对新手很方便，但地址等同于节点本身，所以由用户明确开启。私有仓库途径不需要域名，且服务器 IP 被墙后仍能更新 |
| 检查更新 | 打开菜单时提示，每天最多一次，可关闭，不自动更新 | 新手不会主动去看有没有新版本；只提示不代劳，避免脚本在用户不知情时变化 |
| 外部功能 | BBR、WARP 自己写；证书工具和隧道程序锁版本随脚本管理 | 不在运行时执行别人的在线脚本 |
| 防火墙 | 只在已启用的防火墙里按需放行，且先询问 | 擅自安装防火墙组件曾导致用户原有防火墙被卸载 |
| 发布方式 | 同一个脚本分四个阶段逐步增加功能 | 用户始终只有一条安装命令，更新后新功能直接出现在菜单里 |
