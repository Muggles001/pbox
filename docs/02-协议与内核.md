# 协议与内核

## 一、协议总表

**已实现的是 VLESS-Reality-Vision、Hysteria2、TUIC、AnyTLS 和经 Argo 隧道的 VLESS-WS。** 表中其余协议是规划。

每种协议固定由一个内核运行。只有被用到的内核才会安装。

抗封、速度两栏是经验性评价，会随封锁策略和线路变化，仅用于排序推荐。

| 协议 | 内核 | 需要域名 | 传输 | 抗封 | 速度 | 定位 | 阶段 |
|---|---|---|---|---|---|---|---|
| VLESS-Reality-Vision | sing-box | 否 | TCP | 高 | 高 | 默认主力 | 1 |
| Hysteria2 | sing-box | 否 | UDP | 中 | 很高 | 默认提速 | 1 |
| VLESS-Reality-XHTTP | Xray | 否 | TCP | 高 | 中高 | 主力备选 | 2 |
| VLESS-Reality-gRPC | Xray | 否 | TCP | 中高 | 中 | 可选 | 2 |
| TUIC v5 | sing-box | 否 | UDP | 中 | 高 | 可选 | 2 |
| AnyTLS | sing-box | 否 | TCP | 中高 | 高 | 可选 | 2 |
| ShadowTLS v3 + SS2022 | sing-box | 否 | TCP | 中 | 高 | 可选 | 2 |
| Shadowsocks 2022 | sing-box | 否 | TCP/UDP | 低 | 很高 | 仅建议做中转落地 | 2 |
| SOCKS5 | sing-box | 否 | TCP | 无 | 很高 | 仅建议做中转落地 | 2 |
| VLESS-WS + Argo 临时隧道 | sing-box + cloudflared | 否 | — | 高 | 中低 | IP 被墙时兜底；已实现 | 2 |
| Trojan-TLS | Xray | 是 | TCP | 中高 | 高 | 域名模式 | 3 |
| NaiveProxy | sing-box | 是 | TCP | 高 | 中高 | 域名模式 | 3 |
| VLESS-WS-TLS | Xray | 是 | TCP | 高（套 CDN） | 中低 | 隐藏真实 IP | 3 |
| VLESS-XHTTP-TLS | Xray | 是 | TCP | 高（套 CDN） | 中 | 隐藏真实 IP | 3 |
| VMess-WS-TLS | Xray | 是 | TCP | 中 | 中低 | 兼容老客户端 | 3 |
| VLESS-WS + Argo 固定隧道 | sing-box + cloudflared | 是 | — | 高 | 中低 | 长期兜底；已实现 | 3 |

## 二、每种协议一句话

**无域名**

- **VLESS-Reality-Vision**：让服务器在外人看来像某个知名网站，不需要自己的域名和证书。当前最省心的方案。
- **VLESS-Reality-XHTTP**：同样基于 Reality，换了一种传输方式，流量形态更接近普通网页请求。
- **VLESS-Reality-gRPC**：同样基于 Reality，使用 gRPC 传输。部分线路上更稳，部分客户端支持不佳。
- **Hysteria2**：基于 UDP，丢包严重的线路上速度优势明显。代价是 UDP 可能被运营商限速。
- **TUIC v5**：同样基于 UDP，特性与 Hysteria2 相近，作为另一个选择。
- **AnyTLS**：较新的协议，着重消除"加密里面套加密"的流量特征。需要较新的客户端。
- **ShadowTLS v3 + SS2022**：先和一个真实网站完成握手，再在同一连接里传 Shadowsocks 数据。
- **Shadowsocks 2022**：轻量、快，但流量是全随机字节，直连过墙容易被识别。
- **SOCKS5**：**没有加密**。只应在两台服务器之间使用，默认只允许指定来源访问。

**需要域名**

- **Trojan-TLS**：用自己的域名和正规证书，流量就是标准的加密网页连接。
- **NaiveProxy**：直接复用 Chrome 的网络实现，流量指纹与真实浏览器一致。
- **VLESS-WS-TLS、VLESS-XHTTP-TLS**：可以套在 Cloudflare 后面，外界只看到 CDN 的地址。速度取决于 CDN 线路。
- **VMess-WS-TLS**：较老的方案，保留它是为了兼容不支持 VLESS 的客户端。

**隧道**

- **Argo 临时隧道**：不需要域名，也不需要开放任何端口。隧道地址每次重启都会变，只适合应急。
- **Argo 固定隧道**：地址固定，需要 Cloudflare 账号和托管在其上的域名。

Argo 承载的是一个只监听本机的 WS 入站，加密由 Cloudflare 一侧完成。

## 三、内核归属的理由

| 归属 | 协议 | 理由 |
|---|---|---|
| Xray | Reality 系列、XHTTP | 由 Xray 项目提出并首先实现，XHTTP 仅 Xray 支持 |
| Xray | Trojan、VLESS-WS、VMess-WS | 两个内核都支持。归到 Xray，与 Reality 系列同内核，只用这几种的用户不必装第二个内核 |
| sing-box | Hysteria2、TUIC、AnyTLS、NaiveProxy、ShadowTLS | sing-box 对这些协议的服务端支持完整 |
| sing-box | Shadowsocks 2022、SOCKS5 | 归到 sing-box，便于只装单内核的用户也能用上 |

同一种协议不会同时由两个内核运行。这是一条[硬冲突规则](03-冲突规则.md)。

### 为什么 Reality-Vision 改由 sing-box 承载

最初的设计是由 Xray 承载。实测发现行不通：Xray 自 v26.7.11 起收紧了 Reality 的握手要求，会拒绝 sing-box 客户端和 Mihomo（Clash 系客户端的内核），两个项目的维护者都表示不会为此适配。

在测试机上做的交叉实验：

| 服务端 | Xray 客户端 | sing-box 客户端 |
|---|---|---|
| Xray v26.11.9 | 通 | **不通**，报"reality verification failed" |
| sing-box 1.14.4 | 通 | 通 |

所以改由 sing-box 承载。附带的好处是推荐档只需要一个内核，内存占用更小。Reality-XHTTP 仍只有 Xray 支持，届时它的兼容范围会在界面上标明。

## 四、三档预设

| 档位 | 无域名时 | 填了域名后追加 |
|---|---|---|
| 推荐 | Reality-Vision、Hysteria2。Argo 节点需在协议管理里启用 | — |
| 全家桶 | 推荐档 + Reality-XHTTP、Reality-gRPC、TUIC、AnyTLS、ShadowTLS | Trojan-TLS、NaiveProxy、VLESS-WS-TLS、VLESS-XHTTP-TLS、VMess-WS-TLS |
| 自选 | 任意勾选 | 任意勾选 |

Shadowsocks 2022 和 SOCKS5 不进入任何预设，只能在自选里勾选，并且会触发警告。

## 五、节点输出格式

| 格式 | 说明 |
|---|---|
| 分享链接 | 每个节点一条，各客户端通用 |
| 二维码 | 系统装有 `qrencode` 时在终端显示；没有则提示如何安装，不强制 |
| sing-box 客户端配置 | 完整的 JSON 文件，含全部节点 |
| Mihomo（Clash）配置 | 完整的 YAML 文件，含该客户端支持的节点 |
| 订阅地址 | 默认关闭。已实现推送到自己的 GitLab 私有仓库，不需要域名；由服务器自己提供的方式待域名模式 |

所有格式都在本机生成，不调用任何在线转换服务。某个客户端不支持某种协议时，对应配置文件里会略过并注明。
