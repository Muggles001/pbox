# 冲突规则

用户可以同时运行很多协议，但有些组合互相矛盾。脚本在这些时刻做检查：

- 安装前
- 添加或删除协议
- 修改端口、域名
- 开启或关闭 CDN、端口跳跃
- 修改出口与分流

冲突分两级：**硬冲突**必须取舍，不解决就不能继续；**软冲突**只是警告，确认后放行。

## 一、硬冲突

| 编号 | 冲突 | 原因 | 脚本给出的选项 |
|---|---|---|---|
| H1 | 多个协议要用同一个 TCP 端口（最常见的是 443） | 一个端口只能有一个程序监听 | 选一个占用，其余换端口或不装 |
| H2 | 多个协议要用同一个 UDP 端口 | 同上 | 同上 |
| H3 | Hysteria2 端口跳跃的范围覆盖了其他 UDP 协议的端口 | 跳跃靠转发规则实现，范围内的端口流量都会被转给 Hysteria2 | 自动缩小范围避开，或二选一 |
| H4 | 同一种协议被分配给两个内核 | 重复监听，且凭据不同步 | 只保留一个 |
| H5 | 同一个域名既开了 CDN 又用于直连协议 | 开 CDN 后域名指向 CDN，Trojan、NaiveProxy 这类直连协议会连不到服务器 | 改用两个子域名，或只保留一类 |
| H6 | Hysteria2 同时开"伪装成 HTTP/3"和"Salamander 混淆" | 开混淆后流量不再像 HTTP/3，两种思路互斥 | 二选一，并说明各自适合的情况 |
| H7 | 同一个域名同时使用自签证书和正规证书 | 一个域名同一时间只能提供一张 | 二选一 |
| H8 | 需要 80 端口，但它已被现有网站占用 | 证书申请和伪装站要用 80 | 改用不占 80 的验证方式，或取消。**不动现有网站** |
| H9 | 设了两个默认出口（如 WARP 与链式中转） | 一条流量只能走一个出口 | 选一个做默认，另一个只能用于按域名分流 |
| H10 | 同一个域名被分流规则指向两个出口 | 规则矛盾 | 选一个 |
| H11 | "屏蔽回国流量"与"国内网站走本机出口" | 规则直接矛盾 | 二选一 |
| H12 | 端口已被脚本以外的程序占用 | 无法监听 | 换端口。显示占用者名称，不结束对方进程 |
| H13 | 域名模式下，两个协议要用同一个域名分流（如 Trojan 与 NaiveProxy） | 443 靠域名区分把连接交给谁，一个域名只能对应一个去处 | 给其中一个换子域名，或只保留一个 |

### 关于 443 的补充

443 最抢手，规则 H1 在这里分两种情况：

- **NaiveProxy 换到其他端口会明显削弱伪装**，提示里会特别说明。
- **无域名时，TCP 443 只能给一个协议。** 没有域名可用来区分连接，H1 照常生效。
- **域名模式下，443 由 Nginx 按域名分流，多个协议可以共用。** Reality、Trojan、NaiveProxy、套 CDN 的节点各用一个不同的域名即可同时在 443 上，不算冲突。此时要检查的是 H13：同一个域名不能分给两个协议。例外是 Trojan 和 VLESS-WS-TLS：它们和伪装站共用一个域名，Trojan 靠密码、WS 靠路径区分，不需要各占一个域名。结构见[技术架构](08-技术架构.md)。
- **UDP 443 始终只能给一个协议**，Hysteria2 与 TUIC 之间按 H2 取舍。

## 二、软冲突

| 编号 | 情况 | 风险 | 提示内容 |
|---|---|---|---|
| S1 | 启用 Shadowsocks 2022、VMess 直连 | 流量特征明显，容易被识别 | 建议只用于中转落地 |
| S2 | 启用 SOCKS5 | 没有加密，内容对中间网络可见 | 必须指定允许访问的来源地址才能继续 |
| S3 | 同时启用的协议很多 | 对外暴露的端口多，一个协议被识别可能连累整个 IP | 显示将暴露的端口总数 |
| S4 | Reality 伪装域名与 VPS 所在网络不相称 | 例如小厂商机房的 IP 自称是大厂网站，容易引起怀疑 | 建议改用自动挑选的结果 |
| S5 | 为不支持指纹固定的客户端生成"跳过证书验证"的链接 | 连接可被中间人冒充 | 默认只输出带指纹固定的链接；确需时才另外生成，并建议绑定域名改用正规证书 |
| S6 | 节点地址模式选"合并" | 走 IPv4 还是 IPv6 由客户端决定，本地 IPv6 有问题时会受影响 | 建议同时保留分开的节点 |
| S7 | 关闭"屏蔽访问私网地址" | 节点可能被用来访问 VPS 的内部网络 | 说明风险，默认不建议 |

## 三、提示的样子

硬冲突：

```
这两个协议都要用 TCP 443，只能给其中一个

  A  VLESS-Reality-Vision    不需要域名，伪装效果依赖 443
  B  AnyTLS

  1 A 用 443，B 换端口（推荐）
  2 B 用 443，A 换端口
  3 只装 A
  4 只装 B
```

软冲突：

```
! Shadowsocks 2022 直连容易被识别
  建议只在两台服务器之间使用

  回车 取消     y 仍然启用
```

约定：

- 说清"谁和谁"、"为什么"、"有哪些选择"三件事。
- 推荐项排第一并标注。
- 硬冲突没有"忽略"选项。
- 软冲突的默认动作是取消，继续需要明确输入。

## 四、实现方式

每个协议在自己的模块里声明属性，规则引擎只看属性，不认识具体协议。新增协议时不需要改引擎。

| 属性 | 含义 | 示例 |
|---|---|---|
| `id` | 协议标识 | `reality-vision` |
| `core` | 所属内核 | `xray` |
| `l4` | 传输层 | `tcp`、`udp` |
| `port_pref` | 首选端口，空表示随机 | `443` |
| `port_strict` | 不在首选端口是否削弱伪装 | `yes`（NaiveProxy） |
| `needs_domain` | 是否需要域名 | `no` |
| `cdn` | 域名可否开 CDN | `forbid`、`allow`、`require` |
| `cert` | 证书需求 | `none`、`self`、`acme` |
| `sni` | 域名模式下用于分流的域名；有值即可与其他协议共用 443 | 直连域名、CDN 域名 |
| `risk` | 启用时触发的软冲突编号 | `S1` |

检查流程：

1. 读取"将要生效"的全部状态，而不是当前状态。
2. 逐条跑硬冲突规则。有命中则逐个提问，每答一题重新检查，直到没有硬冲突。
3. 跑软冲突规则，逐条确认。
4. 全部通过后才进入配置生成。

无人值守模式（`--yes`）下，遇到硬冲突直接报错退出并列出冲突，不替用户做选择。
