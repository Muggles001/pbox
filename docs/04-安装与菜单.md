# 安装与菜单

## 一、安装前会看到什么

运行安装命令后，脚本先检查环境，然后只显示一屏：

```
即将安装

  协议   VLESS-Reality-Vision    TCP 443
         Hysteria2               UDP 443
         Argo 临时隧道            不占用端口
  内核   Xray  ·  sing-box
  位置   /etc/pbox   /usr/local/lib/pbox

  回车 开始     2 全家桶     3 自选     q 退出
```

按回车之前，脚本不会改动系统里的任何东西。

环境检查的内容：

| 检查项 | 不通过时 |
|---|---|
| 是否 root | 提示如何切换，退出 |
| 系统和架构是否支持 | 说明支持范围，退出 |
| 是否有 IPv4、IPv6 | 自动适配，只生成能用的节点 |
| 要用的端口是否空闲 | 自动换一个，并在上面那一屏里显示实际端口 |
| 是否已装过其他代理脚本 | 停下来询问：共存（避开对方端口）或取消。绝不删除别人的文件 |
| 是否有宝塔等建站面板或现成网站 | 不接管其网页服务；需要域名模式时询问如何共存 |
| 缺少必要工具 | 列出要安装的包，确认后才装 |

## 二、三档安装

| 档位 | 操作 | 装什么 | 适合谁 |
|---|---|---|---|
| 推荐 | 回车 | Reality-Vision、Hysteria2、Argo 临时隧道 | 绝大多数人 |
| 全家桶 | 输入 2 | 所有互不冲突的无域名协议；填了域名再加上域名类协议 | 想一次备齐多种线路 |
| 自选 | 输入 3 | 自己勾选 | 清楚自己要什么 |

三档都遵守同一套[冲突规则](03-冲突规则.md)。推荐档不会触发任何提问；全家桶只在遇到必须取舍的冲突时提问；自选每勾一项都实时显示冲突与警告。

> 阶段 1 的推荐档只含 Reality-Vision 和 Hysteria2，Argo 临时隧道在阶段 2 加入。见[开发路线](09-开发路线.md)。

## 四、主菜单

输入 `pbox` 打开：

```
pbox   ● 运行中    3 个协议 · 1 个用户

  1 节点
  2 体检
  3 协议
  4 用户
  5 设置
  6 进阶
  7 更新
  8 备份
  9 日志
  0 卸载
```

| 项 | 做什么 | 阶段 |
|---|---|---|
| 节点 | 显示分享链接、二维码、客户端配置文件位置 | 1 |
| 体检 | 逐项检查并给出下一步，见[体检与排障](07-体检与排障.md) | 1 |
| 协议 | 添加、删除协议。添加时做冲突检查 | 1 |
| 用户 | 添加、删除用户，每人一套独立凭据；删除后该用户的节点立即失效 | 2 |
| 设置 | 见下表 | 1 起 |
| 进阶 | 见下表 | 2 起 |
| 更新 | 更新脚本和内核。有新版本时菜单顶部会提示；更新前显示版本号和改动摘要，确认后才执行；新配置校验不过自动回滚 | 1 |
| 备份 | 导出、导入全部配置。换机器时用 | 1 |
| 日志 | 查看最近的错误，一键清空 | 1 |
| 卸载 | 按安装清单逐项撤销，可选保留一份备份 | 1 |

### 设置

| 项 | 说明 |
|---|---|
| 端口 | 单独修改某个协议的端口 |
| 伪装域名 | 重新挑选或手动指定 Reality 的伪装目标 |
| 重置密钥 | 重新生成全部凭据，旧链接全部失效 |
| 节点地址模式 | 见下一节 |

### 进阶

| 项 | 说明 | 阶段 |
|---|---|---|
| 端口跳跃 | Hysteria2 在一段端口范围内切换 | 2 |
| BBR | 开启并保证重启后仍生效 | 2 |
| 域名与证书 | 绑定域名、申请证书、自签与正规证书切换 | 3 |
| CDN 与 Argo | 套 Cloudflare 的节点、固定隧道 | 3 |
| 订阅 | 默认关闭。无域名时推送到你自己的私有仓库，按引导填两个令牌即可得到订阅地址；有域名时也可以由服务器自己提供。详见[隐私与安全](05-隐私与安全.md) | 2 起 |
| 检查更新 | 打开菜单时提示新版本，每天最多查一次。可在这里关闭 | 1 |
| 定时重启 | 默认关闭。小内存机器长期运行后变慢时可以开启 | 2 |
| 出口与分流 | WARP、IPv4/IPv6 优先级、按域名分流、链式中转 | 4 |
| 一键迁移 | 被封后换端口、换伪装目标、切到 CDN | 4 |

## 五、节点地址模式（IPv4 / IPv6 / 双栈）

仅在 VPS 同时有 IPv4 和 IPv6 时可用。

| 模式 | 每个协议输出 | 条件 |
|---|---|---|
| 分开（默认） | 两个节点：一个 IPv4、一个 IPv6 | 无 |
| 合并 | 一个节点，地址是域名 | 需要一个同时解析到本机 IPv4 和 IPv6 的域名 |
| 全部 | 以上三个都输出 | 同"合并" |

为什么"合并"必须用域名：一条分享链接里只能写一个地址。写 IP 就只能是 IPv4 或 IPv6 其中之一；写域名，并给域名同时配 A 和 AAAA 记录，客户端才能自己在两者间选择。这个域名只用来指路，不需要证书，所以无域名协议也能用。

- **切换不影响服务**：服务端始终同时监听 IPv4 和 IPv6，切换只重新生成链接，不重启、不断线。
- **选"合并"前先检查**：核对域名的 A、AAAA 记录是否都指向本机，缺哪条明说。
- **合并模式的代价**：走哪条路由客户端决定。本地 IPv6 网络有问题时可能变慢或连不上，所以默认是"分开"。脚本生成的客户端配置文件默认写成优先 IPv4。
- **套 CDN 和 Argo 的节点不受此设置影响**：它们的入口本身就是双栈，始终是一个节点。

## 六、不用菜单的用法

所有菜单操作都有对应命令，方便写进自己的自动化脚本：

| 命令 | 作用 |
|---|---|
| `pbox install --preset recommended --yes` | 无人值守安装推荐档 |
| `pbox install -f <应答文件>` | 按文件里写好的设置安装。文件格式与状态文件相同；同名环境变量也可传入 |
| `pbox install --offline <目录>` | 用本地已下载好的内核文件安装，哈希照常校验 |
| `pbox install --proxy <地址>` | 下载时走指定代理 |
| `pbox add <协议> [参数]` | 添加协议。参数省略或写 `auto` 即自动生成 |
| `pbox change <协议> <项> [值]` | 修改某个协议的端口、伪装域名等 |
| `pbox del <协议>` | 删除协议。默认要确认 |
| `pbox lang` | 切换中文、英文 |
| `pbox nodes` | 输出节点 |
| `pbox qr` | 输出二维码 |
| `pbox doctor` | 体检 |
| `pbox backup <文件>` / `pbox restore <文件>` | 备份、恢复 |
| `pbox uninstall` | 卸载 |

## 七、交互约定

- 每一屏只做一件事，最多一个问题。
- 每个问题都有默认值，回车即采用。
- 任何会改动系统的操作，执行前都显示将要做什么。
- 报错必须包含三样：发生了什么、可能的原因、下一步怎么做。
- 不出现未经解释的英文术语；绕不开的在[术语表](00-术语表.md)里有解释。
- 任何会改动配置的命令都可以加 `--dry-run`，只显示将要发生的变化，不执行。
- 删除和重置默认要确认，`--yes` 才跳过。
- 遇到硬冲突时，`--yes` 也不会替用户做选择，而是报错退出。
