# 安装与菜单

本文描述的是脚本现在的实际行为。

## 一、安装

运行 `bash pbox.sh install`。脚本先检查环境，然后显示一屏：

```
即将安装

  协议   VLESS-Reality-Vision   TCP 443
         Hysteria2              UDP 443
  内核   sing-box 1.14.4
  位置   /etc/pbox   /usr/local/lib/pbox
  限制   屏蔽访问内网地址（可用 pbox set block-private off 关闭）

开始安装吗 [Y/n]:
```

确认之前，脚本不会改动系统。在这之前有一次提问：**直接回车用推荐配置，输入 `c` 自选协议和端口**。

环境检查的内容：

| 检查项 | 不通过时 |
|---|---|
| 是否 root | 提示如何切换，退出 |
| 系统和架构是否支持 | 说明支持范围，退出 |
| 是否有 IPv4、IPv6 | 自动适配，只生成能用的节点 |
| 要用的端口是否空闲 | Reality 依次试 443、8443 等常见端口；Hysteria2 的 443 被占则随机 |
| 是否已有其他代理脚本或建站面板 | 提醒并询问是否继续，不动对方的文件 |
| 网卡上是内网地址 | 询问"是不是只转发指定端口的 NAT 机器"，默认不是。多数云主机属于"不是" |
| 缺少必要工具 | 列出要安装的包，确认后才装 |

**NAT 机器**（只有服务商转发出来的几个端口）：回答"是"之后，脚本逐个协议告诉你内网端口和协议，让你去服务商后台加转发，再把外网端口填回来。留空表示这台机器不装那个协议。

安装结束后会显示节点链接，并自动跑一次体检。

## 三、协议管理

先列出全部协议，已启用的显示端口。选中一个协议后进入它的子菜单。**新手不需要进这里**，默认值都能用；想调整的在这里改。

| 协议 | 选项 | 说明 |
|---|---|---|
| 所有协议 | 修改端口 | 可指定，也可随机 |
| | 停用 / 启用协议 | 停用后它的节点立即失效 |
| | 外网端口 | 仅 NAT 机器：服务商转发出来的端口 |
| VLESS-Reality-Vision | 伪装目标 | 重新自动挑选，或手动指定域名 |
| | 握手特征 | 进阶：客户端模仿哪种浏览器。chrome、firefox、safari、ios、android、edge、random |
| | 更换密钥 | 进阶：只换这个协议的密钥，不动用户凭据和其他协议 |
| Hysteria2 | 端口跳跃 | 自动选一段、自己指定范围，或关闭 |
| | 流量混淆 | 进阶：QUIC 本身被针对时开启。开启后流量不再像 HTTP/3 |
| TUIC | 拥塞算法 | 进阶：bbr、cubic、new_reno |
| VLESS-WS-Argo | 优选地址 | 从内置的几个里选、自己填，或不用 |
| | 固定隧道 | 域名不变，需要自己的域名和 Cloudflare 账号 |
| | 临时隧道 | 什么都不用填，但域名每次重启会变 |
| | 修改路径 | 进阶：更换 WebSocket 路径 |
| | 连接端口 | 进阶：客户端连 Cloudflare 的哪个端口。443、2053、2083、2087、2096、8443。某个端口被限速时可以换 |
| | 握手特征 | 进阶：同上 |
| Trojan | 握手特征 | 进阶：同上。要先开伪装站，见下文 |
| VLESS-WS-TLS | 优选地址 | 设了套 CDN 的子域名后出现，选法同 Argo |
| | 修改路径、握手特征 | 进阶：同上 |
| VLESS-Reality-XHTTP | 伪装目标、修改路径、握手特征 | 同 Reality-Vision 和 WS。只有通用链接，见下表 |
| ShadowTLS | 握手对象 | 握手借用的真实网站，选法同伪装目标 |
| | 握手特征 | 进阶：同上 |
| Shadowsocks-2022 | — | 只有端口可改 |

几个协议能用的客户端不一样：

| 协议 | 通用链接（v2rayN、v2rayNG 等） | Clash 系、sing-box 配置 |
|---|---|---|
| VLESS-Reality-XHTTP | 有 | 没有：Xray 的 Reality 服务端会拒绝这两类客户端的握手，sing-box 也不支持 XHTTP |
| ShadowTLS | 没有：它没有通用的链接写法 | 有 |
| Shadowsocks-2022 | 有 | 有 |

Shadowsocks-2022 的流量是全随机字节，直接过墙容易被识别，主要用来做服务器之间的中转落地，或者放在 ShadowTLS 里面用。它在同一个端口上同时用 TCP 和 UDP，防火墙两个都要放行。每个用户有自己的密钥，重置用户时跟着变。


### 固定隧道的设置步骤

顺序跟随 Cloudflare 后台的流程，分两步：

1. 在后台"联网 → Tunnels"创建隧道，复制安装命令里 `--token` 后面的那一长串，填进脚本。脚本立刻用它连接，并告诉你是否连上。**不需要在机器上执行后台给的那条安装命令。**
2. 连接器显示在线后，在隧道页面点"添加路由"，选"已发布的应用程序"，填好子域名和域，Service URL 填 `http://localhost:端口`（端口由脚本显示，注意是 http）。保存后把完整主机名填回脚本。

### 优选地址

优选只改变客户端"先连到哪里"，流量仍由 Cloudflare 送回你的隧道。设了优选之后，每条隧道会同时输出两个节点：直连隧道域名的，和走优选地址的。优选失效时直连的仍然可用。嫌节点多时可以开"参数设置 → 精简节点列表"，只留优选节点。

哪个优选更快因地区和运营商而异，需要自己换着试。同一个优选地址在临时隧道和固定隧道上的表现也可能不同。

## 四、用户管理

每个用户一套独立的凭据。列表里选中某个人后可以查看他的节点和订阅地址、重置凭据、指定可用协议、删除；输入 `a` 添加新用户。

| 操作 | 效果 |
|---|---|
| 添加 | 生成一套新凭据。添加时会问他能用哪些协议，回车表示全部 |
| 可用协议 | 指定他能用哪些协议。名单之外的协议里没有他的凭据，他连不上，节点和订阅里也不出现 |
| 重置 | 他手里的旧链接立即失效，其他人不受影响 |
| 删除 | 他的节点立即失效；他在订阅仓库里的文件也会被删掉 |

节点文件按人分开放在 `/etc/pbox/nodes/users/<名字>/`。最后一个用户不能删除。

每个已启用的协议至少要有一个用户能用，否则脚本会拒绝这次修改。名单为"全部"的用户会自动获得之后新启用的协议；指定了名单的用户不会。

多用户的用途是分别发放、分别收回。脚本不统计也不限制每个人的流量，需要这些功能请使用带用户管理的面板。

## 五、订阅管理

把各客户端格式的节点文件推送到你自己的 GitLab 私有仓库。开启后节点有任何变化都会自动推送，**订阅地址不变**，客户端刷新即可。

| 订阅 | 适用客户端 |
|---|---|
| 通用 | v2rayN、v2rayNG、Shadowrocket、Loon、NekoBox、Hiddify |
| Clash 系 | Mihomo、Clash Verge、FlClash、Stash |
| sing-box | sing-box 各平台客户端 |

多用户时每人有各自的订阅地址，内容只包含他能用的协议。名为 `default` 的用户的地址保持不变，其他用户的文件名带一段随机后缀。"订阅地址"一项会把每个人的地址一屏列出，按名字分段，把对应的那段发给他即可。

### 多台机器合并成一个订阅

几台机器填**同一个仓库**，它们的节点就会合并到同一个订阅地址里。令牌不必相同，只要都能访问这个仓库。

加入的办法有两种：在新机器上运行 `pbox sub setup` 手动填写；或者在已经开好订阅的机器上选"机器管理 → 添加机器"，把它给出的那条命令粘贴到新机器上执行。后一种不用再输入项目路径和令牌，但那条命令里含有令牌，只应在你自己的机器之间复制。

合并后的规则：

- 用户按名字对应。两台机器上都有名为 `alice` 的用户，她就只有一个订阅地址，里面是她在两台机器上的全部节点。各台机器上她能用的协议可以不同。
- 你自己（`default`）的订阅地址里是所有机器上 `default` 的节点。
- 任何一台机器的节点有变化，都会自动重新合并，地址不变。
- 每台机器有一个备注，显示在它的节点名前面和机器列表里，默认是自动识别的地区缩写。机器多了分不清时，在"机器管理 → 修改备注"里改成自己认得的名字，如 `JP-BWG`。
- 两台机器备注相同时，后加入的那台自动改成带序号的（如 `JP2`），并提示你。
- "机器管理 → 查看列表"显示这个订阅里合并了哪些机器。
- 关闭订阅或卸载时，本机的节点会从订阅里撤出。机器已经不在了、来不及撤出时，在任意一台还在的机器上选"移除机器"。

两台机器在同一时刻推送时，后完成的那次可能没包含另一台刚才的改动。下一次任意一台推送时会自动补上，也可以手动点一次"立即推送"。

**用户之间不是严格隔离的**：所有人的订阅地址用的是同一个只读令牌，它能读到仓库里每个人的文件。懂行的用户可以看到别人的节点。需要严格隔离时，请直接发链接而不要发订阅地址。添加用户时脚本会说明这一点。

需要准备：一个私有项目、一个 `api` 权限的可写令牌、一个只有 `read_repository` 权限的只读令牌。建议为此单独注册一个 GitLab 账号，原因见[隐私与安全](05-隐私与安全.md)。

## 六、参数设置

| 项 | 说明 |
|---|---|
| 重置密钥 | 重新生成全部用户的凭据和协议密钥，旧链接失效 |
| 地址模式 | IPv4、IPv6 分开输出，或用一个域名合并。见下一节 |
| 机器备注 | 节点名前的名字，如 HK、JP-BWG。可自动识别地区、手动填写或关闭 |
| 屏蔽内网 | 默认开启，防止节点被当作跳板 |
| 更新提示 | 打开菜单时是否检查新版本，每 6 小时最多联网一次 |
| 防火墙 | 在已启用的 ufw 或 firewalld 里放行节点端口 |
| 切换语言 | 中文 / English |
| WARP出口 | 开启、按网站分流、全部走 WARP、关闭、验证是否生效 |
| BBR 加速 | 改善丢包线路上 TCP 节点（Reality、AnyTLS）的速度。只在内核已支持时开启，不更换内核 |
| 域名证书 | 用自己的域名申请受信任的证书，见下文 |
| 精简节点列表 | 默认关闭。开启后同一条路只列一个节点，见下文 |
| 卸载脚本 | 按安装清单清理，不留残留 |

状态区的流量是整台机器默认网卡的计数，重启后归零，用来留意有没有接近服务商的月流量上限。脚本不按用户统计流量。

### 精简节点列表

优选地址和 Argo 隧道会让同一条路出现好几个节点：设了优选时，普通版本和优选版本各一个；临时隧道和固定隧道同时开着时，又各一套。它们是互为后备的，但列在一起容易挑花眼。

开启"精简节点列表"（`pbox set compact-nodes on`）后：

| 情况 | 只列 |
|---|---|
| 同一条路有优选节点（如 WS-CDN 与 WS-CDN-Pref、Argo-Fixed 与 Argo-Fixed-Pref） | 优选节点 |
| Argo 的固定隧道和临时隧道都开着 | 固定隧道的节点 |

链接、客户端配置和订阅都跟着变。节点体检仍然测试全部，所以优选地址失效时体检会指出来，换一个或关掉精简即可。IPv4 与 IPv6 各一个节点不在精简范围内，那是地址模式的设置。

### BBR

开启时只写入两条系统参数，放在脚本自己的一个文件里；关闭或卸载时删掉并恢复原来的值。系统本来就在用 BBR 时不做任何改动。共享内核的容器（OpenVZ、LXC）里这项设置由宿主机决定，脚本会说明无法修改。BBR 只影响 TCP，对 Hysteria2、TUIC 没有作用，它们有自己的拥塞控制。

### 域名证书

有自己的域名时可以开启。开启后 Hysteria2、TUIC、AnyTLS 改用受信任的证书：客户端按正常方式验证，不再需要指纹固定，TUIC 和 AnyTLS 的通用链接也不再跳过证书验证。Reality 和 Argo 不受影响，它们本来就不用自己的证书。

准备工作只有一步：到域名的解析后台加一条 A 记录，指向这台机器的 IP。域名在 Cloudflare 上时，这条记录要关掉代理（灰色云朵）。

然后在"参数设置 → 域名证书 → 设置域名"里填入域名。脚本先检查，有问题会在申请之前指出：

| 检查 | 不通过时 |
|---|---|
| 域名有没有解析记录 | 告诉你要加一条指向哪个 IP 的记录 |
| 解析到的是不是本机 | 显示现在解析到哪里，并提醒 Cloudflare 的代理开关 |
| 80 端口是否空闲 | 显示是哪个程序占用 |
| 是不是只转发指定端口的 NAT 机器 | 说明这种机器要改用"接口验证" |

要知道的事：

- 证书由 Let's Encrypt 签发。申请和以后每次续期，签发方都要访问本机的 80 端口，所以服务商的安全组里要放行它。本机启用了 ufw 或 firewalld 时脚本会自动放行。
- 脚本每 12 小时检查一次，临近到期时自动续期并重启内核。体检会报告证书到期时间和域名是否仍指向本机。
- 想确认续期确实可行，可以运行 `pbox domain renew force`：不等到期，按真实续期的流程重新验证并签发一次。签发方对同一组名字每周最多签 5 张，不要反复运行。
- 证书的签发记录是公开的，任何人都能查到这个域名申请过证书。介意的话用一个不暴露身份的子域名。
- 开启和停用都会让这三个协议的旧链接失效，开了订阅的客户端刷新即可。
- 停用后回到自签证书，原来的指纹不变。

#### 接口验证：不需要 80 端口

域名托管在 Cloudflare 上时，可以选"域名证书 → 接口验证"，或 `pbox domain set 域名 dns`。脚本通过 Cloudflare 的接口临时加一条解析记录来证明域名是你的，签发方不需要访问这台机器。所以：

- 不需要 80 端口，只转发指定端口的 NAT 机器也能用；
- 域名不必解析到这台机器，连 A 记录都可以不加。节点地址仍然是 IP，域名只用来验证证书。

需要一个 Cloudflare 接口令牌：后台右上角头像 → 配置文件 → API 令牌 → 创建令牌 → 选"编辑区域 DNS"模板，"区域资源"里只选这一个域名。申请时如果报找不到域名，再给令牌加上"区域 → 区域 → 读取"权限。

令牌会保存在这台机器上只有 root 能读的位置，因为每次续期都要用。停用域名证书或改用其他验证方式时会清除。

#### 没有域名：给本机 IP 申请证书

"域名证书 → 使用 IP"，或 `pbox domain set ip`。效果与域名证书相同，区别在于：

| | 域名证书 | IP 证书 |
|---|---|---|
| 需要 | 一个域名 | 什么都不需要 |
| 有效期 | 两到三个月 | 约 6 天 |
| 80 端口 | 申请时和两三个月一次的续期时要能访问 | 必须一直能访问，每三四天续一次 |
| 连接里的网站名字 | 你的域名 | 不带 |
| 公开的签发记录里出现的 | 域名 | 本机 IP |

IP 证书把"十年不用管的自签证书"换成了"每几天必须续期成功一次"的证书。连续几天续期失败，这三个协议就会连不上；体检在剩余不足 2 天时报错。它换来的好处是 TUIC 和 AnyTLS 的通用链接不再跳过证书验证。所以它是可选项，默认不开。

目前只支持公网 IPv4。域名证书和 IP 证书二选一，可以随时互相切换或停用。

#### 伪装站

有了域名证书（不能是 IP 证书）之后可以开启："域名证书 → 伪装站点"，或 `pbox site on`。开启后用浏览器访问你的域名，看到的是一个正常的网页；Reality 仍然在 443 上，链接不变。

做法是让 Nginx 接管 TCP 443，只看连接开头写明的域名、不解密内容：访问你域名的交给网站，其余的原样交给 Reality。

| 项 | 说明 |
|---|---|
| Nginx | 机器上没有时用系统的软件包安装。脚本只用它的程序，配置和服务都是自己的，不读也不改 `/etc/nginx` |
| 机器上已有网站 | 443 被别的程序占用时脚本会说明并退出，不动原有的网站 |
| 站点来源 | 默认是一个内置的简单页面，标题、文字和配色随机生成。可以把自己的页面放进 `/etc/pbox/site/`，或用 `pbox site source https://某网站` 改成转发一个真实的网站 |
| 关闭 | `pbox site off`，Reality 回到直接监听 443 |
| 与其他设置的关系 | 开着伪装站时不能停用域名证书或改用 IP 证书，要先关闭伪装站。AnyTLS 和网站用同一个域名，不能也放在 443 上 |

内置页面只是后备。所有装了本脚本的机器都有相似的页面，认真看是能看出来的，所以更建议换成自己的内容或转发一个真实网站。转发别人的网站时，请选一个你有理由与之关联的站点。

Reality 换到别的端口后就不再经过分流，443 上只剩网站。

#### 伪装站上的 Trojan 和 VLESS-WS-TLS

开了伪装站之后，协议管理里可以启用这两个协议，或 `pbox add trojan`、`pbox add vless-wstls`。它们和网站用同一个域名、同一个 443，链接里的地址是域名，证书是正规的，不需要跳过验证。

| 协议 | 怎么藏在网站里 |
|---|---|
| Trojan | 连接先交给它，密码对得上就是代理，对不上就把连接转给网站。浏览器打开域名，看到的还是那个网页 |
| VLESS-WS-TLS | 网站上的一个随机路径。只有带着这个路径发起 WebSocket 的请求才会转给代理，浏览器直接打开这个路径得到 404 |

它们不在安装时出现，因为要先有域名证书和伪装站。挂着它们时不能关伪装站，先停用它们。VLESS-WS-TLS 的路径可以在协议设置里换；两者都可以换握手特征。

#### 套 CDN

VLESS-WS-TLS 可以经 Cloudflare 的 CDN 连接，客户端连的是 Cloudflare，外界看不到这台机器的 IP；还可以配优选地址。和 Argo 的区别是不经过隧道，Cloudflare 直接回到这台机器的 443。需要你的域名托管在 Cloudflare 上。

步骤：

1. 在 Cloudflare 上加一条记录，例如名字 `cdn`、类型 A、内容是本机 IP。先保持灰色云朵（仅 DNS）。
2. "域名证书 → 套 CDN"，或 `pbox site cdn cdn.你的域名`。证书会重签一次，同时写上直连域名和这个子域名。
3. 回到 Cloudflare，把这条记录打开代理（橙色云朵）。"SSL/TLS"页面的加密模式选"完全（严格）"。
4. 节点体检会经 Cloudflare 真实访问一次子域名，确认回源正常。

完成后 VLESS-WS-TLS 多一个经 CDN 的节点；在协议设置里设了优选地址，再多一个优选节点。优选失效时前一个仍然可用。直连节点不受影响。

| 要点 | 说明 |
|---|---|
| 为什么要另一个子域名 | 打开代理后这个名字解析到 Cloudflare，直连协议（Trojan、直连的 WS）用它会连不上，所以直连域名不能打开代理 |
| 加密模式管的是整个域名 | 同一个域名下还有别的打开了代理的网站时，改模式会影响它们。可以不动全局，只给这个子域名加一条配置规则（Rules → Configuration Rules），把加密模式设成"完全（严格）" |
| 只有 WS 能套 | Cloudflare 只转发网页请求。Trojan 和其他协议不经过它 |
| 连接端口 | 只用 443。Cloudflare 回源时用的是客户端连它的那个端口，而这台机器只在 443 上接 |
| 已经打开代理时设置 | 用 HTTP 验证申请证书时，Cloudflare 可能拦下验证请求。失败时把记录临时改回灰色云朵再设 |
| 续期 | 自动进行。Cloudflare 的"始终使用 HTTPS"不跳转证书验证的路径，开着也不影响。万一验证请求被自己加的跳转规则改成 HTTPS，也会经伪装站转给续期程序 |
| 停用 | `pbox site cdn off`。证书重签成只有直连域名，之后可以删掉那条记录 |

### WARP 出口

用于目标网站不欢迎机房 IP 的情况。它改变的是服务器访问目标网站时的出口，和客户端到服务器这一段无关。

默认只让预置的几个网站走 WARP，可以整份换成自己的名单，输入 `default` 恢复预置值。"验证出口"会经由节点实际访问一次，报告是否真的走了 WARP。

## 七、节点地址模式

主要用于 VPS 同时有 IPv4 和 IPv6 的情况。菜单顶部会显示本机是双栈还是只有一种地址；只有一种时，"分开"下每个协议本来就只有一个节点，选另外两种是额外给出（或换成）用域名做地址的节点。

已经设置了域名证书时，选"全部"或"合并"会直接用那个域名，不再让你填一遍。

| 模式 | 每个协议输出 | 条件 |
|---|---|---|
| 分开（默认） | 两个节点：一个 IPv4、一个 IPv6 | 无 |
| 全部 | 分开的节点，再加一个域名节点 | 需要一个同时解析到本机 IPv4 和 IPv6 的域名 |
| 合并 | 只有一个域名节点 | 同上 |

一条分享链接里只能写一个地址，所以"一个节点同时带双栈"必须用域名。这个域名只用来指路，不需要证书。切换模式不影响服务，只重新生成链接。

Argo 节点不受此设置影响，它的入口本身就是双栈。

## 八、全部命令

菜单里的每个操作都有对应的命令。

| 命令 | 作用 |
|---|---|
| `pbox` | 打开菜单 |
| `pbox install` | 安装。可加 `-f 应答文件`、`--offline 目录`、`--proxy 地址` |

| `pbox qr` | 终端二维码，需要系统装有 qrencode |
| `pbox doctor` | 体检。加 `--report` 输出隐去 IP 和域名的报告 |
| `pbox add <协议> [端口]` | 启用协议 |

| `pbox change <协议> port <端口\|auto>` | 改端口 |
| `pbox change <协议> ext-port <端口>` | NAT 机器的外网端口 |
| `pbox change <reality-vision\|reality-xhttp\|shadowtls> sni <域名\|auto>` | 换伪装目标（ShadowTLS 是握手对象） |
| `pbox change reality-vision keys` | 只换 Reality 的密钥 |

| `pbox change vless-ws edge-port <端口>` | Argo 节点连 Cloudflare 的端口 |
| `pbox change hysteria2 hop <on\|off\|起-止>` | 端口跳跃 |
| `pbox change hysteria2 obfs <on\|off>` | 流量混淆 |
| `pbox change tuic cc <bbr\|cubic\|new_reno>` | TUIC 的拥塞算法 |

| `pbox bbr [on\|off\|status]` | BBR |
| `pbox site [status\|on\|off\|source <builtin\|网址>]` | 伪装站与 443 分流 |
| `pbox site cdn <子域名\|off>` | 套 CDN 的子域名 |
| `pbox domain [status\|set 域名 [dns]\|set ip\|off\|renew [force]]` | 域名证书。加 `dns` 用 Cloudflare 接口验证；`set ip` 是没有域名时给本机 IP 申请；`renew force` 不等到期立即续一次，用来确认续期可行 |

| `pbox rollback` | 回到上一份成功运行的配置 |
| `pbox backup [文件]`、`pbox restore 文件` | 备份、恢复 |
| `pbox log [clear]` | 查看、清空日志 |
| `pbox update` | 更新脚本与内核 |
| `pbox uninstall` | 卸载 |
| `pbox lang` | 切换语言 |

协议名：`reality-vision`、`hysteria2`、`vless-ws`、`tuic`、`anytls`。

TUIC 和 AnyTLS 的分享链接没有携带证书指纹的写法，所以用自签证书时，"通用"订阅和单条链接里它们会跳过证书验证；Clash 系和 sing-box 订阅里仍然使用指纹固定。启用时脚本会说明这一点。设置了域名证书后没有这个问题。

两个通用开关：

| 开关 | 作用 |
|---|---|
| `--yes` | 不提问，全部采用默认值。遇到必须取舍的冲突时直接报错退出，不替你选；有风险的操作（软冲突）也不会被它放行 |
| `--dry-run` | 只显示将要发生的改动，不执行 |

无人值守安装时可以用环境变量传入设置，例如 `PBOX_PROTOCOLS`、`PBOX_REALITY_PORT`、`PBOX_HY2_PORT`、`PBOX_XHTTP_PORT`、`PBOX_STLS_PORT`、`PBOX_SS_PORT`、`PBOX_REGION`；NAT 机器用 `PBOX_REALITY_EXT_PORT`、`PBOX_HY2_EXT_PORT`。

## 九、交互约定

- 每个问题都有默认值，回车即采用。
- 会改动系统的操作，执行前都显示将要做什么。
- 报错包含三样：发生了什么、可能的原因、下一步怎么做。
- 删除和重置默认要确认。
- 进阶选项不出现在安装流程里，只在协议管理的子菜单中，并标明"进阶"。
