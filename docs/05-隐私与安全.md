# 隐私与安全

## 一、谁能看到什么

先说清楚边界。自建节点能挡住的和挡不住的：

| 对象 | 能看到 | 看不到 | 对应措施 |
|---|---|---|---|
| 本地运营商、中间网络 | 你在连接某个海外 IP，流量大小和时间 | 访问了哪些网站、内容 | 加密与伪装，见[伪装与抗封锁](06-伪装与抗封锁.md) |
| VPS 服务商 | 你的 VPS 连了哪些目标地址；理论上可读取 VPS 上的一切 | — | 选可信的服务商；服务端默认不落访问日志 |
| 目标网站 | VPS 的 IP | 你的真实 IP | — |
| 本脚本的作者 | 什么都看不到 | — | 零遥测，代码明文可查 |
| 第三方订阅转换站 | 如果你把链接贴上去，就能看到全部节点信息 | — | 脚本本地生成所有格式，不需要用到它们 |

**自建节点不等于匿名。** VPS 是用你的账号租的，服务商知道你是谁。

## 二、脚本自身

| 措施 | 说明 |
|---|---|
| 零遥测 | 不统计安装量，不上报任何信息 |
| 明文单文件 | 不加密、不混淆；运行时不下载其他脚本 |
| 下载校验 | 内核、cloudflared、证书工具全部锁定版本，并核对脚本内写死的 SHA256，不符即中止。因此即使改走镜像下载，文件也无法被替换 |
| 获取公网 IP | 优先读取本机网卡；只有读不到（例如 NAT 机器）时才访问外部服务，并在使用前告知是哪一个 |
| 发布可验证 | 每个版本附带脚本文件的 SHA256 |
| 联网克制 | 打开菜单时会检查脚本有没有新版本：每天最多一次，只访问项目的发布页，可以关闭。除此之外，打开菜单、查看节点不产生网络请求 |
| 二维码本机生成 | 不使用在线二维码服务，节点链接不会离开服务器 |
| 下载保持证书校验 | 不为了"下得下来"而关闭校验 |

### 你需要信任谁

用一键脚本，本质上是在信任写脚本的人。口碑再好的作者，账号也可能被盗，项目也可能转手。圈内就发生过一键包被收购后植入后门的事。所以本项目的做法是把需要信任的东西降到最少：

| 风险 | 做法 |
|---|---|
| 作者的服务器被攻破或作恶 | 脚本不依赖作者自有的任何服务器。内核等文件只来自上游官方发布页，哈希写死在脚本里 |
| 脚本在你不知情时变了 | 脚本装在本机，不会自行更新，快捷命令也不会重新拉取远程代码 |
| 项目转手后新版本被植入恶意代码 | 更新只能由你主动触发；更新前显示新版本号和改动摘要，由你确认。每个版本公布哈希，安装命令指向固定版本 |
| 仓库被平台停用 | 提供镜像仓库。有哈希校验，从镜像安装同样可验证 |
| 你没时间通读全部代码 | 所有访问网络、改动系统的代码集中在少数几个模块里，文档标明位置，重点看这几处即可 |

### 默认启用的限制

脚本默认启用的限制只有一项：**屏蔽访问私网地址**，目的是防止节点被当作跳板。它在安装确认页里列出，可以在设置里关闭。除此之外，脚本不屏蔽任何网站；回国流量、BT 的屏蔽都要你自己开启。

## 三、服务端默认设置

| 项 | 默认值 | 说明 |
|---|---|---|
| 访问日志 | 关闭 | 不记录客户端 IP 和访问目标 |
| 错误日志 | 仅错误级别 | 体检需要；可一键清空 |
| 运行账号 | 专用的非 root 账号 | 内核被攻破时限制影响范围。属主与权限的设置与 Xray 官方安装脚本一致 |
| 服务加固 | 开启系统提供的隔离选项 | 限制内核进程可读写的路径和可获得的权限 |
| 密钥与状态文件 | 仅 root 可读 | 权限 600 |
| 访问私网地址 | 屏蔽 | 防止节点被当作跳板访问 VPS 内网或云厂商的内部接口 |
| 回国流量 | 可选屏蔽 | 减少 VPS IP 与国内服务的关联；与"国内网站走本机"互斥 |
| BT 下载 | 可选屏蔽 | 避免 VPS 因版权投诉被停机 |
| 服务端 DNS | 可选改用加密 DNS | 避免 VPS 商的解析器看到查询记录 |

## 四、凭据

- **全部随机生成**：用户标识、密码、Reality 密钥、路径都由内核自带的生成命令产生，不使用任何固定默认值。
- **每个用户一套**：多用户时凭据互相独立，删除一个用户不影响其他人。
- **一键重置**：怀疑泄露时在"设置"里重置，旧链接立即全部失效。
- **不回显**：菜单和日志里不显示完整密钥；只有"节点"页面输出完整链接。

## 五、订阅

默认关闭。开启后：

- 地址包含随机长路径，无法被猜到。
- 只通过加密连接提供，不会用明文。有三种途径，见下表。
- 可一键更换地址，旧地址立即失效。
- 不经过任何订阅转换服务，各客户端格式都在本机生成。

| 途径 | 需要 | 节点信息放在哪 | 特点 |
|---|---|---|---|
| 推送到你自己的私有仓库 | 一个 GitLab 账号 | 你名下的私有仓库 | 不需要域名；服务器 IP 被墙时订阅仍能更新，换了端口或地址后客户端自动拿到新节点 |
| 域名模式 | 域名 | 只在你的服务器上 | 不经过任何第三方 |
| Argo 固定隧道 | Cloudflare 账号和域名 | 只在你的服务器上 | 不需要开放端口 |

关于私有仓库这一途径，需要知道的事：

- **这是把节点信息存到了第三方平台上。** 仓库是私有的、归你所有，但平台方理论上能看到内容。介意的话用另外两种途径。
- **全程由你控制。** 账号、仓库、令牌都是你自己创建的，脚本只在你填入后使用，随时可以在平台上撤销。
- **用两个令牌。** 一个可写，只留在服务器上用于推送；一个只读，写进订阅地址给客户端用。这样订阅地址即使泄露，别人也改不了你的订阅内容。
- **订阅地址等同于节点本身**，不要发到公开场合。泄露后撤销只读令牌即可让旧地址失效。
- 推送用平台的接口直接完成，不安装 git，也不保存你的账号密码。

## 六、备份

备份文件包含全部密钥，等同于节点本身。

- 导出时默认要求设置密码并加密。
- 导出文件权限为仅 root 可读。
- 备份只保存在本机，脚本不会把它上传到任何地方。
- 恢复时先在临时目录解开并走完整的校验流程，通过后才替换现有配置；失败则现有配置原样保留。
- 提示用户不要通过聊天软件明文传输未加密的备份。

## 七、求助时的脱敏

`pbox doctor --report` 生成的报告自动隐去 IP、域名和全部密钥，可以直接公开粘贴。

## 八、脚本不做的事

| 不做 | 原因 |
|---|---|
| 修改 SSH 配置、root 密码 | 超出职责，改错会把用户锁在外面 |
| 安装或替换防火墙 | 可能破坏用户原有规则 |
| 修改系统 DNS | 只改内核自己的出站 DNS，不动系统设置 |
| 停用防火墙、关闭 SELinux、清空规则 | 为了"装得上"而让服务器门户大开，得不偿失 |
| 使用共享的回退凭据 | 注册或生成失败就报错，不会让多个用户共用同一组密钥 |
| 自动更新 | 有新版本只提示，是否更新由用户决定。后台默认只有证书续期这一项定时任务 |
