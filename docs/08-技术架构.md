# 技术架构

面向开发者。

## 一、核心思路

**状态文件是唯一事实来源，内核配置是生成物。**

菜单和命令的每个操作只修改状态文件，然后由同一套流程把状态渲染成内核配置。不对内核配置做就地修改，因此不需要 jq。

生成物**按协议拆成多个文件**，交给内核自己合并加载：Xray 用 `-confdir`，sing-box 用 `-C`。改一个协议只重写一个文件。

## 二、服务器上的布局

```
/etc/pbox/
├── state/                  唯一事实来源，备份只需要这个目录
│   ├── global.env          地址模式、域名、语言、日志级别等
│   ├── protocols/          每个已启用的协议一个文件
│   │   └── reality-vision.env
│   ├── users/              每个用户一个文件
│   │   └── default.env
│   └── outbound.env        出口与分流
├── generated/              由状态渲染得到，不手改
│   ├── xray/               00_base.json、10_reality-vision.json ……
│   ├── sing-box/           00_base.json、10_hysteria2.json ……
│   └── nginx/              域名模式的分流与伪装站配置
├── previous/               上一份成功运行的状态与生成物，回滚用
├── custom/                 高级用户的自定义片段，随内核一并加载
│   ├── xray/
│   └── sing-box/
├── certs/                  证书与私钥
├── nodes/                  分享链接与客户端配置文件
└── manifest                安装清单，卸载时据此还原

/usr/local/lib/pbox/
├── pbox.sh                 脚本本体
├── versions.env            锁定的版本与各架构的 SHA256
└── bin/
    ├── xray
    ├── sing-box
    ├── cloudflared
    ├── acme.sh
    └── previous/           上一个版本，用于回滚

/usr/local/bin/pbox         指向 pbox.sh 的入口
```

权限照搬 Xray 官方安装脚本的模型：配置目录 `root:pbox 0750`，配置文件 `0640`，私钥仅运行账号可读。

系统服务（只创建用到的）：

| 服务 | 作用 |
|---|---|
| `pbox-singbox` | sing-box 内核。目前所有协议都由它承载 |
| `pbox-argo` | cloudflared 临时隧道 |
| `pbox-argo-fixed` | cloudflared 固定隧道 |
| `pbox-hop` | 开机时恢复端口跳跃的转发规则 |
| `pbox-xray` | Xray 内核。管理代码保留，目前没有协议使用它 |

服务名带前缀，与系统里可能已有的 `xray`、`sing-box` 服务互不干扰。

### 自定义片段

`custom/` 里的文件由内核与生成物一起合并加载，并参与校验。脚本不读取、不修改它们。自定义片段导致校验失败时，报错会指明是 `custom/` 里的哪个文件。

## 三、一次改动的生效流程

所有会改变配置的操作都走同一条路：

1. 加锁，防止两个脚本进程同时改动。然后合并设置，优先级：本次命令行参数 > 已保存的状态 > 默认值。结果写入状态的**临时副本**。
2. 对临时副本做[冲突检查](03-冲突规则.md)。
3. 渲染出全部生成物。
4. 分别用 `xray run -test -confdir` 和 `sing-box check -C` 校验。
5. 与当前生成物逐文件比对。**没有变化的内核不动。**
6. 把当前状态与生成物存入 `previous/`。
7. 原子替换。
8. 让有变化的内核生效：sing-box 用信号热重载，连接不断，失败再重启；Xray 重启。
9. 探活：确认进程存活、端口已监听。
10. 第 4 步或第 9 步失败则恢复 `previous/`，然后向用户报告原因。

用户看到的要么是"已生效"，要么是"未生效，已恢复原状，原因是……"，不会停在半成功的状态。

`--dry-run` 走到第 5 步为止，显示将要变化的内容后退出。

## 四、版本管理

内核、cloudflared、acme.sh 一视同仁。

| 规则 | 说明 |
|---|---|
| 版本锁定 | `versions.env` 写明每个组件经过测试的版本号和各架构的 SHA256 |
| 模板随版本 | 每个内核大版本对应一套配置模板。内核出现破坏性变更时，新模板和新版本号在同一次脚本发布里更新 |
| 更新路径 | "更新"先更新脚本，再把组件升到新脚本锁定的版本。不提供"升到上游最新版" |
| 回滚 | 旧版本保留在 `bin/previous/`，校验或探活失败时自动换回 |
| 离线安装 | 可指定本地已下载好的文件，也可指定代理；哈希照常校验 |
| 下载 | 多个组件并行下载。默认从官方发布页直连。直连失败时询问是否改走镜像。因为哈希写死在脚本里，镜像无法替换文件内容；校验不符即中止 |
| 不在运行时执行远程脚本 | 包括证书工具的安装脚本 |

### 外部功能怎么来

原则：**能自己写清楚的自己写；必须用成熟工具的，锁版本、验哈希后随脚本管理。任何情况下都不在运行时下载并执行别人的在线脚本。**

| 功能 | 方式 | 说明 |
|---|---|---|
| BBR | 自己写 | 只是检查内核、写两项系统设置、读回确认，十几行的事 |
| WARP | 自己写 | 直接调用 Cloudflare 的注册接口取得密钥和地址，写成内核自带的 WireGuard 出站。不安装 WARP 客户端，不引入第三方注册程序 |
| 端口跳跃、防火墙放行、服务管理 | 自己写 | 只调用系统已有的命令 |
| 自签证书、密钥、用户标识 | 内核自带命令 | 不依赖额外工具 |
| 正规证书 | acme.sh，锁版本 | 它本身是一个成熟的大型 Shell 工具，重写既不现实也不安全。做法是下载指定版本的文件并校验哈希，不运行它的在线安装脚本，关闭它的自动升级 |
| Argo 隧道 | cloudflared 官方程序，锁版本 | 同上 |
| 二维码 | 系统软件包 qrencode | 可选 |

与"运行时执行远程脚本"的区别在于：版本固定、内容可验证、不会在用户不知情时变化。

## 五、域名模式的 443

没有开启伪装站时，内核直接监听各自的端口，不安装 Nginx。

开启伪装站后，由 Nginx 在 TCP 443 上**按握手里的域名分流，不解密**。这是现在已经实现的结构：

```
TCP 443 ── Nginx（只看握手里的域名）
            ├─ 自己的域名      → Nginx 自己的网站（用域名证书）：伪装站
            └─ 其余全部        → sing-box：Reality 入站（监听本机端口）
                                 包括 Reality 的伪装目标、不认识的域名、不带域名的连接，
                                 所以这些连接的表现与没有分流时完全相同

UDP 443 ── sing-box：Hysteria2（不经过 Nginx）
```

Reality 没有启用或不在 443 上时，"其余全部"由网站那一侧拒绝握手（Nginx 1.19.4 及以上），不把证书亮给只知道 IP 的扫描者。

| 要点 | 说明 |
|---|---|
| 本机连接 | Nginx 到内核之间走本机回环地址上的随机端口。不向内核传递客户端的真实地址，因为本项目默认不记录它 |
| Nginx 来源 | 发行版软件包及其分流模块，不从源码编译 |
| 与系统的 Nginx 的关系 | 只用它的程序。配置是脚本自己的一份，服务是自己的，以内核同一个专用账号运行；不读取也不修改 `/etc/nginx`。软件包自带的那个服务，只有在机器原本没装 Nginx 时才停掉 |
| 纳入同一套流程 | Nginx 的配置和内核配置一起渲染、校验、替换、探活、回滚。校验不过或起不来时整体退回 |
| 切换过程 | 443 在内核和 Nginx 之间易手时，先处理让出端口的一方。客户端链接不变 |
| 已有网站 | 检测到 443 被别的程序占用时不接管，直接说明并退出 |

计划中的后续（尚未实现）：直连域名上的 Trojan（认证失败回落到伪装站）、同一域名按路径转给 WS 入站、套 CDN 的域名。届时每种协议用各自的子域名参与分流。

## 六、证书

| 项 | 做法 |
|---|---|
| 工具 | acme.sh，锁版本并校验哈希，放在自己的目录里 |
| 验证方式 | （现状：申请和续期时临时监听 80 端口完成验证，或通过 Cloudflare 接口验证；以下为最初的设计）默认通过 Nginx 的网页目录完成，不需要腾出 80 端口。为此常驻一个只用于验证的 80 端口入口，申请时不改动主配置；80 不可用时改用 DNS 验证（需要 DNS 服务商的令牌） |
| 申请前预检 | 域名解析是否指向本机、是否误开 CDN、80 端口是否可达 |
| 签发方 | 首选失败时自动换另一家；全部失败则保持原状并说明原因 |
| 续期 | 定时任务自动续期；续期后先测试配置，通过才重载，并且只重载用到该证书的服务；失败在体检中提示。证书工具不开启自动升级 |
| 自签证书 | 用内核自带命令生成，域名随机；配合指纹固定使用，见[伪装与抗封锁](06-伪装与抗封锁.md) |

## 七、Argo 隧道

| 项 | 做法 |
|---|---|
| 承载 | 一个只监听本机的 WS 入站，加密由 Cloudflare 一侧完成 |
| 传输 | cloudflared 使用 HTTP/2，不依赖 UDP 出站 |
| 临时隧道地址 | 从 cloudflared 的本地接口读取，不解析日志。每次重启会变，脚本随之重新生成链接 |
| 固定隧道 | 用户提供令牌和域名 |

### 协议模块的约定

每个协议文件实现同一组函数，其余代码不需要认识具体协议：

（阶段 1 的两个协议最初计划分属两个内核，现在都由 sing-box 承载，见[协议与内核](02-协议与内核.md)。）

| 函数 | 作用 |
|---|---|
| `meta` | 声明属性，供冲突引擎使用。字段见[冲突规则](03-冲突规则.md) |
| `defaults` | 生成该协议的初始状态：端口、密钥等 |
| `render_inbound` | 根据状态输出该协议的入站配置文件 |
| `render_front` | 域名模式下输出该协议在 Nginx 分流里的条目，可选 |
| `share_link` | 根据状态、用户、地址输出分享链接 |
| `client_singbox` | 输出 sing-box 客户端的出站片段 |
| `client_mihomo` | 输出 Mihomo 的节点片段；不支持时返回空 |
| `selftest` | 在本机临时起一个客户端，经由该协议实际访问一次外网 |
| `doctor` | 该协议的体检项，通常就是调用自测 |
| `hosts` | 可选。协议自己给出节点地址（Argo 节点不用服务器 IP） |

新增一种协议就是新增一个文件。

### 文案

所有面向用户的文字放在 `i18n/` 的文案表里，逻辑代码只引用编号。阶段 1 提供中文和英文。首次运行按系统语言选择，可用 `pbox lang` 切换。

### 发布

- `build.sh` 把模块合并成一个文件，保留注释，不压缩、不混淆。
- 每个版本打标签发布，附 `pbox.sh` 的 SHA256。
- 安装命令拉取的是已发布版本，不是开发分支。

## 十、与系统的边界

| 事项 | 做法 |
|---|---|
| 防火墙 | 只识别已启用的那一个，放行前询问。规则带 `pbox` 标记，插在第一条拒绝规则之前。不安装、不替换、不停用、不清空 |
| 端口跳跃的规则 | 使用系统已有的 nftables（独立的表）或 iptables（带标记的规则），IPv4、IPv6 各一套；由 `pbox-hop` 在开机时恢复，不安装规则持久化组件 |
| SELinux | 不关闭。需要时为端口添加标签，做不到则说明原因并给出手动命令 |
| BBR | 只开启，不更换内核。先查状态，已开启就不动；确认内核版本够、模块可用、不是不支持的容器环境，否则说明原因后退出。设置写入 `/etc/sysctl.d/` 下的独立文件，重启后仍生效；写完读回确认生效；记入 `manifest`，卸载时撤销 |
| 检查更新 | 打开菜单时检查脚本有没有新版本，有就在菜单顶部提示一行。每 6 小时最多查一次，结果缓存；只访问项目的发布页；超时两秒即放弃，不拖慢菜单；可以关闭。只提示，不自动更新 |
| 其他联网 | 除检查更新外，打开菜单、查看节点不产生网络请求。体检里需要联网的项目会标明 |
| 定时任务 | 默认只有证书续期一项。定时重启内核是可选项，默认关闭，供小内存机器使用 |
| 运行账号 | 创建专用系统账号运行内核，只授予绑定低位端口的能力。服务文件开启禁止提权、私有临时目录、系统目录只读等加固选项；配置错误导致的退出不触发反复重启 |
| 已有的其他代理脚本 | 安装前检测常见脚本的目录和服务，发现则询问共存或取消。不删除对方任何文件 |
| 已有网站 | 检测到 80、443 被网页服务占用时不接管 |
| 安装中途失败 | 按 `manifest` 撤销已经做过的改动，不留下装了一半的状态 |
| 卸载 | `manifest` 记录创建过的每个文件、服务、账号、防火墙规则、系统设置；卸载逐项撤销，全程不需要联网 |

## 十一、网络自适应

| 环境 | 行为 |
|---|---|
| 纯 IPv4 | 只生成 IPv4 节点 |
| 纯 IPv6 | 只生成 IPv6 节点；下载时自动处理仅 IPv6 的可达性 |
| 双栈 | 入站同时监听两栈；按[节点地址模式](04-安装与菜单.md)输出 |
| NAT 机器 | 提示用户填写服务商分配的外部端口，链接里使用外部端口 |

## 十二、测试

| 层次 | 内容 |
|---|---|
| 静态检查 | shellcheck、shfmt，每次提交运行。各模块的函数统一加模块名前缀，并检查有无重名 |
| 渲染测试 | 对每种协议及其组合渲染配置，并用内核的校验命令验证。可在普通容器里运行 |
| 冲突测试 | 每条规则至少一个命中用例和一个不命中用例 |
| 特征审计 | 扫描源码，不允许出现写死的密钥、短标识、路径等线路可见的值；同一环境渲染两次，线路可见的参数除 443 端口外不得相同。理由见[伪装与抗封锁](06-伪装与抗封锁.md) |
| 整机测试 | 在各支持系统的虚拟机上跑"安装 → 体检 → 改设置 → 更新 → 卸载"全流程，卸载后比对系统是否还原 |

整机测试矩阵：Debian 12、Ubuntu 22.04/24.04、Alpine；amd64、arm64；纯 IPv4、纯 IPv6、双栈。
