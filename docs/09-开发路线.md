# 开发路线

始终只有**一个脚本、一条安装命令**。四个阶段是开发顺序：每个阶段完成后发布，用户更新脚本就能在菜单里看到新功能，已有节点和配置不受影响。

## 当前实现状态

整理于 2026-11-12。实际的开发顺序没有严格按下面的阶段走：用户实测时提出的需求被提前了，所以阶段 1 全部完成的同时，阶段 2 到 4 各完成了一部分。

### 已完成但验证不充分

| 项 | 欠缺 |
|---|---|
| Alpine 与 OpenRC | 容器里只验证了下载、哈希和内核对配置的校验；服务管理从未真实运行过 |
| 系统防火墙放行 | 用过的测试机都没有启用 ufw 或 firewalld，这条路径没走到 |
| 端口跳跃的实际跳跃 | 确认了规则存在、外部的包能到达；没有确认客户端真的在端口间切换 |
| 在线更新 | 代码已写，但要等仓库公开并设置发布地址后才能运行 |
| IPv6 与双栈 | 用过的测试机都只有 IPv4 |
| 节点地址的合并模式 | 只有本机测试 |

### 与设计的差距

| 项 | 现状 |
|---|---|
| 防火墙 | 只自动处理 ufw 和 firewalld；自行配置的 iptables、nftables 只提醒 |
| 镜像下载 | 只能通过环境变量 `PBOX_MIRROR` 指定，没有交互询问 |
| 更新前显示改动摘要 | 目前只给出发布页链接 |
| 体检的脱敏报告 | 只隐去 IP 和域名 |
| 日志 | 为了不记录来源 IP，内核日志只留致命错误，排查时信息很少，主要依靠体检 |
| 全家桶预设 | 尚无；目前是推荐配置加自选 |

### 开发中改变的设计决定

| 原设计 | 现在 | 原因 |
|---|---|---|
| Reality 由 Xray 承载 | 由 sing-box 承载 | Xray 自 v26.7.11 起会拒绝 sing-box 与 Mihomo 客户端的 Reality 握手。实测 sing-box 的服务端两种客户端都接受 |
| 推荐配置用两个内核 | 只用 sing-box 一个 | 同上。Xray 的管理代码保留，将来做 XHTTP 时启用 |
| 订阅只挂在自己服务器的加密入口后 | 增加推送到用户自己的 GitLab 私有仓库 | 不需要域名；服务器 IP 被墙后订阅仍能更新 |
| 打开菜单不联网 | 打开菜单时检查更新，每天最多一次，可关 | 新手不会主动查看有没有新版本 |
| 最低支持 Debian 11 | Debian 12 | Debian 11 的软件源已下线。脚本不拦它，机器上工具齐全时仍可用 |
| 内核日志记录错误级别 | 只记致命错误 | 错误级别会把每次失败连接的来源 IP 写进日志 |
| 内置 39 个凭印象列的伪装目标 | 47 个实测通过的 | 最初的名单实测只有 11 个可用 |

### 尚未开始

多用户；ShadowTLS、Shadowsocks 2022、Reality-XHTTP 等其余协议；域名模式（正规证书、伪装站、自有域名套 CDN）；链式中转；Rocky / Alma 支持。

## 阶段 1：骨架

目标：推荐档可用，后续功能所依赖的机制全部就位。

| 内容 | 说明 |
|---|---|
| 状态文件与渲染流程 | 三层合并 → 冲突检查 → 按协议渲染 → 校验 → 比对 → 替换 → 生效 → 探活 → 失败回滚 |
| 双内核管理 | 下载校验、版本锁定、独立服务、专用账号、按需安装 |
| 冲突引擎 | 属性声明 + 规则；本阶段实现 H1、H2、H4、H12，S5、S6 |
| 协议 | VLESS-Reality-Vision、Hysteria2 |
| Reality 伪装目标自动挑选 | 候选实测后随机取 |
| 自签证书指纹固定 | 按客户端写入各自的指纹字段 |
| 节点输出 | 分享链接、二维码、sing-box 与 Mihomo 客户端配置 |
| 节点地址模式 | 分开、合并、全部三种；合并前检查域名解析 |
| 体检 | 通用检查项；生成本地检测命令 |
| 命令行 | `install`、`add`、`change`、`del`、`nodes`、`doctor`；`--yes`、`--dry-run`、应答文件 |
| 设置 | 改端口、换伪装目标、重置密钥 |
| 更新、备份恢复、日志、卸载 | 卸载可离线完成 |
| 隐私默认项 | 关闭访问日志、文件权限、屏蔽私网 |
| 文案 | 中文、英文 |
| 检查更新 | 打开菜单时提示新版本，每天最多一次，可关闭 |
| 自定义片段 | `custom/` 目录 |

验收：

- 全新的 Debian 12、Ubuntu 24.04、Alpine 上，一路回车安装成功，客户端能连上两个节点。
- 纯 IPv4、纯 IPv6、双栈三种机器分别通过。
- 人为占用 443 后安装，脚本自动改用其他端口并在确认页显示。
- 人为写入一份错误配置后触发更新，脚本自动回滚且节点不中断超过一次重启的时间。
- 只改 Hysteria2 的设置时，Xray 进程不重启。
- 篡改下载到的内核文件后，脚本拒绝安装。
- 安装全程只访问上游官方发布页，以及用户同意后的镜像；抓包确认没有其他外部请求。
- 同一台机器重装两次，线路上可见的参数除 443 端口外无一相同；源码扫描不出写死的密钥或标识。
- 备份后在另一台机器恢复，节点可用。
- 卸载后比对系统，无残留文件、服务、账号、规则。

## 阶段 2：无域名协议补全

目标：不需要域名的功能全部到位。

| 内容 | 说明 |
|---|---|
| 协议 | Reality-XHTTP、Reality-gRPC、TUIC v5、AnyTLS、ShadowTLS v3、Shadowsocks 2022、SOCKS5 |
| Argo 临时隧道 | 加入推荐档 |
| 全家桶与自选 | 三档安装齐备 |
| 多用户 | 添加、删除，凭据独立 |
| 冲突规则 | H3、H6，S1 至 S4、S7 |
| 进阶 | Hysteria2 端口跳跃、Salamander 混淆、BBR |
| 隐私 | 屏蔽回国流量、屏蔽 BT、加密 DNS、备份加密、体检脱敏报告 |
| 订阅 | 推送到用户自己的私有仓库；节点有变化时自动重新推送 |
| 定时重启 | 可选，默认关闭 |

验收：

- 全家桶在三种系统上安装成功，每种协议至少用一个客户端验证可连。
- 每条已实现的冲突规则都有可复现的触发方式，提示文案符合约定。
- 删除一个用户后，其所有节点立即失效，其他用户不受影响。
- 重启 VPS 后，BBR 和端口跳跃仍然生效。
- 开启端口跳跃后，系统原有的防火墙规则一条不少。
- 开启私有仓库订阅后改一次端口，客户端刷新订阅即拿到新节点；用只读令牌无法修改仓库内容。

## 阶段 3：域名模式

目标：有域名的用户能用上正规证书、伪装站和 CDN。

| 内容 | 说明 |
|---|---|
| 443 分流 | Nginx 按 SNI 分流，结构见[技术架构](08-技术架构.md) |
| 域名与证书 | 申请前预检；自动续期；签发方自动切换；自签与正规证书切换 |
| 伪装站 | 未认证连接和未知域名都落到网页。内容优先用用户指定的网站或页面，内置模板只作后备 |
| 协议 | Trojan-TLS、NaiveProxy、VLESS-WS-TLS、VLESS-XHTTP-TLS、VMess-WS-TLS |
| CDN | 直连域名与 CDN 域名分开管理；ECH 选项 |
| Argo 固定隧道 | — |
| 订阅 | 挂在加密入口后面，随机路径、可更换 |
| 冲突规则 | H5、H7、H8、H13 |

验收：

- 域名解析错误、80 端口不可达时，脚本在申请证书前就指出问题。
- 浏览器直接访问任一域名看到的都是伪装站。
- Reality、Trojan、NaiveProxy、一个套 CDN 的节点同时在 443 上可用。
- 同一域名误开 CDN 后启用直连协议，触发 H5。
- 机器上已有网站时，脚本不修改其任何配置。
- 证书续期可通过手动触发验证。

## 阶段 4：出口与抗封

目标：解决"目标网站不欢迎"和"被封后恢复"两类问题。

| 内容 | 说明 |
|---|---|
| 出口 | WARP、IPv4/IPv6 优先级、链式中转 |
| 分流 | 按域名指定出口 |
| 冲突规则 | H9、H10、H11 |
| 一键迁移 | 换端口、换伪装目标、切到 CDN 或 Argo |
| 封锁体检 | 四种故障的引导式判断 |
| 进阶伪装 | XHTTP 上下行分离；从服务器所在网络挑选伪装目标 |
| 系统支持 | Rocky / Alma 9+ |

验收：

- 指定域名走 WARP 后，从该域名看到的出口 IP 确为 WARP。
- 两台机器组成链式中转可用。
- 模拟端口被封（防火墙丢弃该端口），按引导完成迁移后节点恢复。

## 已有结论的事项

上一版列为待核实，本轮调研后已有方向：

| 事项 | 结论 |
|---|---|
| 自签证书能否用指纹固定代替跳过验证 | 可以。sing-box 客户端自 1.13 起支持公钥指纹字段；Mihomo、Shadowrocket 各有自己的指纹字段；v2rayN 可内嵌证书。具体字段名写代码时对照各客户端文档 |
| 域名模式的 443 共用结构 | 定为 Nginx 按 SNI 分流 |
| sing-box 的抗量子密钥交换 | 自 1.13 起默认的曲线列表已包含混合抗量子选项，无需额外设置 |
| sing-box 内置的证书申请 | 内联写法已在 1.14 弃用。本项目统一用 acme.sh，不依赖内核的这项功能 |
| XHTTP 上下行分离的链接写法 | 已有现成做法可参照：在分享链接的附加字段里描述下行通道。客户端支持范围仍需核实 |
| 前置服务用 Nginx 还是 Caddy | 用 Nginx。Caddy 的自动证书更省事，但按域名分流而不解密需要额外插件，官方发行版不带 |
| BBR 是否需要换内核 | 不换。只在内核已支持时开启 |
